# 프롬프트 기록

사용자가 전달한 프롬프트(요청) 원문을 시간순으로 기록한다. 새 요청을 받으면 맨 아래에 추가한다.
기능·구현사항으로 정리한 내용은 [SPEC.md](SPEC.md) 에 있다.

## 작업 규칙 (프롬프트로 전달된 상시 지침)

HanilKeyboard 프로젝트의 규칙을 가져왔다. (#2)

- **문서 관리**: 요청을 기능·세부 구현사항으로 정리해 `docs/SPEC.md` 로 관리하고, 결정·요청이 추가될 때마다 갱신한다.
- **자동 커밋**: 작업하면 사용자가 요청하지 않아도 자동으로 커밋한다.
- **커밋 단위**: 하나의 작업으로 분리할 수 있는 작은 단위로 커밋한다.
- **커밋 종류 분리**: 문서 수정, 스타일, 리팩토링, 기능 수정, 기능 추가 등 성격이 다른 변경은 서로 다른 커밋으로 분리한다.
- **브랜치·PR**: 적당한 작업 단위마다 브랜치와 PR 을 만들어 작업한다. 기본 작업 브랜치는 `develop`, 작업 브랜치는 `feature/{번호}-{작업내용}`.
- **PR 병합 전 확인**: PR 을 병합하기 전에 "머지할까요?" 라고 묻는다.
- **브랜치 재사용**: 연속된 요청이 같거나 비슷한 부분을 수정하면 새 브랜치를 만들지 않고 기존 브랜치에서 작업한다.
